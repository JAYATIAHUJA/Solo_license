# Solo License v3 - PR-by-PR roadmap

*12 Oct 2026 · source: `docs/PRD-v3-control-layer.md` · base: `main` after PR #38*

This turns the PRD into a queue of small pull requests. Each PR is one branch, one reviewable idea,
its own tests, and leaves `main` green. Pick the next unchecked row, write its detailed plan in
`docs/superpowers/plans/2026-10-12-<branch-slug>.md` (PR 1's plan is already written), build it,
merge it, then move on.

> **For agentic workers:** each PR row gets its own detailed plan before code. Use
> superpowers:executing-plans or superpowers:subagent-driven-development per plan.

---

## How every PR is built (PowerShell)

```powershell
# 1. Start from a fresh main
git checkout main
git pull
git checkout -b <branch>

# 2. Build with TDD: failing test -> code -> passing test -> commit (repeat)
python -m pytest tests/<file>.py -q          # the tests you are working on
python -m pytest -q                          # everything, before pushing
cd frontend; npm test; npm run build; cd ..  # only when the PR touches frontend/

# 3. Push and open the PR
git push -u origin <branch>
gh pr create --base main --title "<title>" --body-file <notes.md>

# 4. Wait for CI (Backend tests + Frontend tests and build) and the Entire gates
gh pr checks --watch

# 5. Merge (the repo keeps merge commits) and clean up
gh pr merge --merge --delete-branch
git checkout main
git pull
```

**Rules for every PR** (PRD §7 working rules):
- One PR per row below. If a row grows past ~400 changed lines (deletions excluded), split it.
- Commit messages: `feat(coding): ...`, `fix(coding): ...`, `chore: ...`, `docs: ...`, matching history.
- Commit from PowerShell so Entire's checkpoint trailer is attached.
- CI green before merge. A PR that changes what the agent experiences also gets one live
  Claude Code check, noted in the PR body (what you typed, what the agent did).
- Never push to `main` directly.

**PR body template:**

```markdown
## What
<one paragraph: the behaviour that changes>

## Why
PRD v3 <feature id> - <one line>

## How to check
- `python -m pytest -q` -> all pass
- <live check, if any>

## Not in this PR
<what the next PR picks up>
```

### PR 5 - feat/remediation (F3)
- New `sololicense/coding/remediation.py`: one `compose(event, action_class, command, reason, *, checkpoint=None, diff_files=())` -> `Remediation(text, revert_commands)`; agents render it in their own format.
- **PostToolUse failure** on a non-diagnostic class: answer `{"decision": "block", "reason": ..., "hookSpecificOutput": {"hookEventName": "PostToolUse", "additionalContext": ...}}` (Claude Code), `additional_context` (Cursor), block (Codex). Add `render` support in `agents.py` for the `POST_FAIL` event.
- **Repeated forbidden attempt** (3 denies in one turn): add `"interrupt": true` to the PermissionRequest deny.
- **Stop block**: reason names the revert commands (`git checkout -- <files>` / `git stash`) and the Entire checkpoint.
- New table `agent_remediations (id, session_id, turn_id, text, delivered_at)` + `UserPromptSubmit` returns `{"hookSpecificOutput": {"hookEventName": "UserPromptSubmit", "additionalContext": <queued text>}}` and marks it delivered (used by PR 6).
- **Acceptance:** unit tests on `compose`; gate tests for each hook's answer; live Claude Code: a failing `npm install left-pad` is followed by the agent restoring `package.json`/lockfile in the same turn.

### PR 6 - feat/flag-decision (F6 backend)
- New table `agent_flags (id, decision_id, turn_id, actor_id, reason, delivered_at, created_at)`.
- `CodingGate.flag(decision_id=None, turn_id=None, *, actor_id, reason)`: hard reset of the class to L0 (PRD open question 2), `kind='flag'` agent event + ledger commit `flag(<class>@<repo>)`, queues a remediation for the session (PR 5's queue).
- `POST /api/coding/flags` (role APPROVER) with `{decision_id | turn_id, reason}`.
- `GET /api/coding/stream` (SSE) or keep 2 s polling of `/api/coding` - pick polling first (simpler), SSE later.
- **Acceptance:** API test: flag -> license level 0, event `flag`, next `user-prompt` answer carries "Your last turn was flagged by the user: <reason>".

### PR 7 - feat/live-access (F6 UI + F12 Live)
- `Coding.jsx` (or a new `Live.jsx` page): per-repo strip of action classes with level chips that animate up/down when `/api/coding` changes (poll every 2 s).
- "This was wrong" button on each decision and turn row -> reason textbox -> `POST /api/coding/flags`.
- Kill switch already exists (`/api/coding/freeze`); surface it on the Live page.
- **Acceptance:** vitest for the flag button; manual: flag in UI -> level drops < 2 s; screen-record it (demo step 4).

### PR 8 - feat/principals (F2)
- `agents.normalize` reads `agent_id`/`agent_type` (Claude), `subagent_type` (Cursor) -> `principal = "subagent:<type>"`, else `"main"`.
- `agent_licenses` gets `principal TEXT NOT NULL DEFAULT 'main'`; PK `(repo, principal, action_class)` (table rebuild migration in `database.py`).
- Lookup: principal row if present, else repo row capped by `policy.subagents.max` (default 1).
- `agent_decisions`, `agent_turns` get `principal`; `agent_events.principal` filled.
- Subagent failure demotes the subagent row; repo row too only for destructive classes (PRD open question 1), configurable in policy.
- **Acceptance:** subagent at L0 is asked while main at L2 runs alone; subagent failure demotes only the subagent row for `install-dep`.

### PR 9 - feat/subagents (F4)
- Map Claude `SubagentStart`/`SubagentStop`, Cursor `subagentStart`/`subagentStop`, Codex `SubagentStart`/`SubagentStop` in `agents.py` (new gate events `subagent-start`, `subagent-stop`).
- SubagentStart -> `additionalContext` license summary; Cursor can deny by policy.
- PreToolUse/PermissionRequest on tool `Agent`/`Task`: deny types in `[subagents] deny_types`.
- SubagentStop -> run the turn check on its changes and `block` with remediation.
- Installer writes the new hooks; plugin `hooks.json` too.
- **Acceptance:** an `Explore` subagent's `git push` is denied with a reason; an over-editing subagent is sent back at its own stop.

### PR 10 - feat/loop-detection (F9)
- New `sololicense/coding/loops.py`: fingerprint = tool + normalised args; table `agent_fingerprints (session_id, fingerprint, count, last_outcome, last_error)`.
- 3 identical -> guidance via `additionalContext`; 5 -> deny with `interrupt`; same failing command 3x -> "keeps failing for the same reason: <stderr head>; stop retrying".
- Edit thrash (same file edited 4x in a turn) -> turn sent back at Stop.
- Not a demotion.
- **Acceptance:** fixture session that loops is stopped on the 5th repeat.

### PR 11 - feat/session-digest (F5)
- New table `agent_sessions (session_id, agent, repo, started_at, cost_usd, model, digest)`.
- `sololicense/coding/digest.py`: builds the PRD §5 F5 JSON, capped (assert < 32k tokens, ~4 chars/token).
- `jev.py`: one call, several questions (`violates goal/policy`, risk tier, relevance 1-5); low confidence -> ask a person.
- Stop scope grading sends goal + diff hunks, not the whole diff.
- **Acceptance:** fixture: same command judged differently under two goals; size assertion.

### PR 12 - feat/packaging (F10)
- CLI: `init --global` (user-level hooks), `serve --background` (Windows scheduled task first), `doctor` (Claude Code version >= 2.1.251 for `PreModelSwitch`).
- Claude Code plugin: add `PreToolUse` deny path, `SubagentStart/Stop`, opt-in statusline script, the skill (advisory, PRD §3.4).
- Codex: `hooks.json` folder + `/solo-license` prompt.
- **Acceptance:** fresh machine to first gated prompt in < 2 minutes, measured and written in the PR body.
