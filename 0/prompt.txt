  ### (4) Is our lane still empty?
  Within neatHack, yes, as far as I can tell. I grepped all 32 clones for revocation, earned, trust score/level/ledger, autonomy level/tier, probation/demote and PreToolUse.
  
  - **No hackathon repo keeps persistent trust per (repo x action class)** earned from verified outcomes and revoked automatically.
  - **Satianurag/fence:** its "trust score" and PreToolUse hits are scraped issue data (`data/trace_at_created.json`), not logic.
  - **rajkaria/roster:** promote/demote applies to whole agent setups (model/harness) after offline pre-registered experiments (`web/lib/forward.ts`, `experiments/`). It does not gate actions at run time.
  - **faroukobayanju/kedge:** checks verified outcomes within a single run (tests passed, files within allowed globs, false "all pass" claims: `kedge/checks.py` `drift()`, `kedge/supervisor.py` `decide_next`) and rolls back. It grants no lasting autonomy.
  - **MD-Sharik/guardian:** gates each tool call before it runs, but with a stateless model plus thresholds (`guardian-service/app/policy.py`: ALLOW/BLOCK/ESCALATE). It does not learn from outcomes.
  - **Vaibhaav-Tiwari/neatlogs-hack (Tally):** escalates failed tasks to stronger models and enforces spend ceilings. That is routing, not permissions.
  
  Outside the hackathon, the idea itself is not new. Reddytheer/autonomy-ladder (0 stars) and MMVFIRM/UEAL (17 stars) implement earned promotion plus revocation, judging only from their READMEs; I did not read their code. Neither targets coding agents, uses test-pass or diff-scope verification, or ships hooks for Claude Code, Codex or Cursor. Our defensible claim is "first for coding agents, verified by tests and diff scope, enforced across 11 agent hooks", not "first earned autonomy".
